# NAYA — Stakeholder Demo Readiness

Prepared for the Elaine Falconer / Georgie Longman-Turner walkthrough.

## Status: Ready for stakeholder validation, with caveats below

The core admin + contractor onboarding journey works end-to-end and has been
walked live (not just typechecked/tested): login → People dashboard → create
a contractor via the 3-step wizard → review → generate invitation → open the
contractor's invite link → see categorized actions, resources, contacts →
complete a task → see progress and readiness update live.

## Demo sequence (~8 minutes)

1. Open `/login`, sign in.
2. `/dashboard` — show the unified People list, filter to **Contractors**.
3. Open an existing contractor record — point out Ready-to-start status, current phase,
   next action, owner, invitation status.
4. Click **Preview journey** — shows the contractor's experience read-only, with no
   effect on any real invitation.
5. Click into one task in the preview or detail view — show owner, due date,
   dependency, resource link (or "Resource to be confirmed"), and contact for help.
6. Go to **+ Add contractor / associate** — walk the 3-step wizard (engagement type,
   requirements under the 4 headings with Yes/No/To-be-confirmed, review screen showing
   generated task count and any unresolved items).
7. Return to `/dashboard` — point out the new record and its generated invitation.

## Safe URLs

- `/login`
- `/dashboard` and `/dashboard?journey=contractor`
- `/contractors/new`

Do not navigate to a raw `/?token=...` invite link from a real production contractor
during the meeting — generate a fresh one live if the self-serve view needs to be
shown, using **Preview journey** wherever possible instead (it needs no real invite
at all).

## What's safe to show

- All data currently in the admin dashboard (names, projects, statuses) — this is
  real NIIT CAS data and fine to show in context.
- The task engine's generated phases/tasks/dependencies for any new demo record created
  live during the meeting.

## What is NOT included in this file

No raw invitation token appears anywhere in this document or should be pasted into
chat/slides. If a live self-serve view needs to be shown, generate the link in the
moment via **Generate/Replace invitation link** and open it directly — never read it
aloud or screenshot the URL bar.

## A real bug found and fixed during this pass

The invitation links generated by the admin dashboard use `?token=`, but the
contractor-facing page was only listening for `?invite=` — every previously-issued
invitation link was silently non-functional. Fixed in `public/index.html` (now checks
`token` first, falls back to `invite`). This means **any invite link issued before
this fix should be treated as unverified** — regenerate before relying on one in the
demo.

## Known limitations / assumptions for Georgie to confirm

- **Recurring invoice/payment processing** is intentionally out of scope — NAYA tracks
  an "Invoicing setup" task, not an AP/Finance integration.
- **Resource links** for client-required training and project-specific training are
  deliberately shown as "Resource to be confirmed" — no URLs have been validated by
  Georgie yet, so none are fabricated.
- **Client access / client training "can follow induction" policy** is modeled as a
  per-engagement toggle the Resourcing Lead sets at creation (not hard-coded) — Georgie
  should confirm this is the right default behavior per client.
- The **Phase 1 full persona audit** (11 personas) and the **Phase 9 fixture set**
  beyond the 31 automated tests currently in place were not completed in this pass —
  flagging rather than claiming coverage that doesn't exist yet.
- **Phase 8 (full visual/terminology cleanup pass)** was not done as a dedicated pass;
  spot-checked screens look consistent, but a full sweep (mobile layouts, empty/error
  states across every surface) has not been performed.
- The project directory was reconstructed from scratch this session after the
  environment reset mid-task; `pages/snapshot/[id].tsx` (the employee progress-snapshot
  page) was rebuilt from memory and may not be pixel-identical to what was previously
  deployed — worth a quick visual check against production before relying on it in a
  meeting, since it is unrelated to this phase's scope but was regenerated as a
  byproduct of recovery.
